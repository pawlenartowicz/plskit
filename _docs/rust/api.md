# Rust API

The `plskit` Rust crate is the canonical implementation. The public
surface mirrors the [Python API](../python/api.md) — same function
names, same argument names, same result-field names ([naming](../internals/naming.md)).
What differs is language-bound: case, types, and call syntax.

The full, always-current API reference lives on docs.rs and is
regenerated by `cargo doc` on every release: **<https://docs.rs/plskit>**.
This page does not duplicate that reference — read docs.rs for the
authoritative signatures and trait bounds. The role of this page is
orientation and side-by-side examples for users moving between languages.

## Surface at a glance

The crate is organized around three thematic groups, the same as the
Python wrapper:

- **Core fit / predict** — `pls1_fit`, `pls1_predict`, `preprocess`. K-selection lives in `pls1_find_k_optimal` and `pls1_find_k_sequence`.
- **Sparse PLS1** — `spls1_fit`, `spls1_find_keep_optimal`, `spls1_find_k_optimal`, `spls1_find_k_sequence`. `keep ∈ [1, n_features]`; `keep = n_features` reproduces the dense functions bit-exactly. One axis is always fixed: no joint `(k, keep)` 2-D search. Prediction uses `pls1_predict` on the `Pls1Model` returned by `spls1_fit` — no separate `spls1_predict`. Per-coordinate β CIs are not offered under selection (post-selection inference, deferred to a separate spec).
- **Inference** — `pls1_confirmatory_test` (with the five methods `raw_perm` / `split_nb` / `split_perm` / `score` / `e`), `pls1_perm_null`. CIs ride on `pls1_confirmatory_test(ci=true)` plus the standalone `pls1_rotation_stability`.
- **Interpretive** — `rotate` with pluggable `L` and method-axis `(method, args)` dispatch.

### Planned — not yet implemented

The following names are roadmap items and do **not** compile in the current crate:
`pls2_fit`, `pls3_fit`, `plssvd_fit`, `pls1_robust_fit`, `mbpls_fit`,
`pls2_predict`, `pls3_predict`, `pls2_transform`, `pls3_transform`,
`grassmannian_alignment_test`, `anisotropic_null`.

For per-function need / arguments / options / why-core entries, read
the [Python API](../python/api.md) — the entries are language-agnostic.
Argument names match exactly; types follow Rust convention (`faer::Mat`
where Python sees `np.ndarray`, `Option<u64>` where Python sees
`int | None`, and so on).

## Sparse PLS1 signatures

The four sparse entry points and their Rust types, for reference alongside
the Python signatures in [api.md](../python/api.md) §2b:

```rust
pub fn spls1_fit(
    x: MatRef<f64>,
    y: ColRef<f64>,
    k: KSpec,           // KSpec::Fixed(usize) — no string modes
    keep: usize,        // keep ∈ [1, n_features]
    weights: Option<ColRef<f64>>,
    opts: FitOpts,
) -> PlsKitResult<Pls1Model>
// Pls1Model.keep: Option<usize> — Some(keep) for sparse fits, None for dense.

pub fn spls1_find_keep_optimal(
    x: MatRef<f64>,
    y: ColRef<f64>,
    k: usize,
    weights: Option<ColRef<f64>>,
    opts: FindKeepOptimalOpts,
    // FindKeepOptimalOpts: n_folds (default 5), seed, disable_parallelism, verbose
) -> PlsKitResult<FindKeepOptimalOutput>
// FindKeepOptimalOutput: keep_star, k, cv_scores, cv_scores_se, keep_grid, seed, n_eff

pub fn spls1_find_k_optimal(
    x: MatRef<f64>,
    y: ColRef<f64>,
    k_max: usize,
    keep: usize,
    weights: Option<ColRef<f64>>,
    opts: FindKOptimalOpts,
) -> PlsKitResult<FindKOptimalOutput>
// Same result type as pls1_find_k_optimal.
// selector="bic" reuses the dense penalty — upward k bias under sparsity (deliberate v1).

pub fn spls1_find_k_sequence(
    x: MatRef<f64>,
    y: ColRef<f64>,
    k_max: usize,
    keep: usize,
    weights: Option<ColRef<f64>>,
    opts: FindKSequenceOpts,
) -> PlsKitResult<FindKSequenceOutput>
// Same result type as pls1_find_k_sequence.
```

`keep = n_features` produces bit-exact output for all four functions.
`spls1_find_keep_optimal` sweeps a logged geometric grid (powers of two,
endpoints always included) and selects the sparsest `keep` within 1 SE of
the best mean CV R²; the swept grid is in `FindKeepOptimalOutput.keep_grid`.

## Side-by-side example

Fitting PLS1 with three components:

```rust
// Rust
use plskit::pls1_fit;
let result = pls1_fit(&x, &y, 3, /* options... */);
```

```python
# Python
import plskit
result = plskit.pls1_fit(X, y, k=3)
```

Function name and arguments match; types and call syntax follow each
language's conventions. The same is true for every other function on
the public surface.

## Result types

Result structs carry the same field names as the Python dataclasses
(snake_case, matching across languages), with Rust types in place of
NumPy / Python equivalents — see [results](results.md) for the full
field-by-field map.

## Stability

The Rust crate is the canonical implementation; wrapper crates call into
it. Argument names, function names, and result-field names are stable
across versions; numerical outputs are reproducible only when the version
is fixed. Updating the version may change results.
